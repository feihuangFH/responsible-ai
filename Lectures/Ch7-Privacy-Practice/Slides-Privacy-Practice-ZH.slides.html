第一部分 — 从原则到实践

工作流程

  1. 识别准标识符 并评估重新识别风险
  2. 选择匹配的隐私增强技术(PET):k-匿名性、差分隐私(DP)或合成数据生成
  3. 应用该技术
  4. 衡量权衡取舍,将效用损失与剩余披露风险相权衡
  5. 判断决策,是否可接受,并记录该决策

案例研究:三位接收方,一个数据集

该保险公司的数据治理政策要求,任何保单级数据离开公司之前,都必须经过一次 DPIA 式的风险评估(第六章)并获得批准。目前同时收到了三份申请:

  1. 一家再保险公司,正在为合约续保定价,希望获得保单级数据以构建自己的定价模型——并且已经从往年的分保合约中掌握了该业务组合的部分背景信息。
  2. 保险公司自己的定价团队,正在构建明年的费率模型,需要真实感的数据,但无论如何都会针对生产环境的真实数据进行验证。
  3. 一家基准测试供应商,为监管机构的市场行为审查提供服务,只需要按定价因子划分的汇总统计量——完全不需要记录级文件。

同一个数据集,同样的监管背景,却是三种不同的风险状况。等本章三种技术都有了实际数字支撑之后,我们会回到这里。

DPIA 即数据保护影响评估:组织在启动一项新的或风险更高的个人数据用途之前,所进行的一次正式的、结构化的风险评估,已在第六章介绍。以这一案例研究开篇的意义在于:“应该使用哪种 PET”对于同一个数据集而言,并非只有单一固定答案——它取决于谁是接收方,以及对方究竟需要什么,这正是第六章场景一致性内容所论证的观点。

💬 讨论(4分钟)— 案例研究

  • 哪一位接收方可以被正当地提供 k-匿名化 数据?再保险公司所掌握的部分背景信息,是否会改变你的答案?
  • 定价团队并不严格需要真实记录,只需要真实感的数据。这是否意味着必须使用合成数据,还是说存在一个更简单、更经济的答案,考虑到该团队是内部团队?

先不要急着下结论。 我们将在接下来的两个小时里,逐步建立起真正的证据:k-匿名性的抑制模式、差分隐私噪声与 n 的权衡关系、合成数据的 TSTR 与 NNDR 结果,并在结尾“案例研究揭晓”一页,用实际数字重新回答这三个问题。

第二部分 — 重新识别风险

准标识符

并非直接标识符,但可与外部数据组合以重新识别个人。

  • 性别 与其他变量组合时缩小群体范围
  • 年龄段 是最具识别性的变量之一
  • 密度段 是邮编/位置的代理变量
  • 价值段 基于车辆价值,在极端值处缩小候选范围
  • 折扣等级段 基于无理赔历史,在同一年龄组内缩小候选范围

理赔是保单持有人在事故后向保险公司提出的赔付请求。折扣等级段反映无赔款折扣水平,无理赔年数越多,折扣等级越高。这五个变量,恰恰是案例研究中的再保险公司最有可能已经掌握部分信息的变量,这也是为什么“已掌握部分背景信息”在后文会如此重要。

衡量风险

指标 数值
全局重新识别风险 0.77%(样本量大,分组较宽)
预期重新识别数量 765,占100,000条记录中的一部分
k = 1 的记录数(唯一) 6
罕见组合(k ≤ 5) 102,高度可被重新识别

全局数字低估了真实风险。 再保险公司可能已经知道业务组合中包含哪些客户。他们只需核实,而不必从零开始识别。

个体风险 r_k = 1/f_k,其中 f_k 是与某条记录在准标识符取值组合上完全相同的记录数(即其等价类规模)。全局风险则是这些个体风险相加后,表示为数据集的一个比例。sdcMicro 实际使用的估计方法是一个超总体模型 (Franconi 和 Polettini 2004年),但 1/f_k 是其直觉:取值组合越罕见,风险就相应越高。这个数字也正是案例研究中再保险公司风险状况的依据——765并非预期为零,而再保险公司恰恰是这765人中,最有可能已经认识其中一部分人的接收方。

聚合问题

每一个准标识符单独看都是无害的:

男性 → 不具识别性 · 66岁以上 → 不具识别性 · 豪华车 → 不具识别性

组合起来,它们会大幅缩小候选范围。这正是第六章 Solove 的聚合问题的量化体现:全部记录 → 男性 → 男性且66岁以上 → 男性、66岁以上、豪华车 → 男性、66岁以上、豪华车、密集城区。群体规模迅速收缩。

这一具体组合,男性、66岁以上、豪华车,在该数据集中的规模为 n = 487。请记住这个数字:它会在差分隐私部分作为“罕见子群体”基准再次出现,用来展示当一个群体从大变小时,差分隐私噪声会发生怎样的变化。

💬 讨论(4分钟)

每一个准标识符单独看都是无害的。组合起来,却能唯一识别出某个人。

界限在哪里?组合多少个变量才算“风险过高”而不能发布?

一种思考方式: 并不存在一个普遍适用的固定数字,真正重要的是最终组合有多罕见,而不是涉及了多少个变量。这正是 k-匿名性接下来要做的事:设定一个阈值 k,并将任何规模小于 k 的组合都视为风险过高,而不管具体涉及多少个变量。

第三部分 — k-匿名性

应用 k = 50 匿名化

sdcMicro 的局部抑制,即对规模小于 k 的群组,抑制其最具识别性的取值。

|\{r' \in D : r'[Q] = r[Q]\}| \geq k

为什么是 k = 50,而不是教科书式的 k = 5? 100,000条记录中只有102条低于 k = 5——在 k=5 下抑制几乎不会触及这个数据集。k = 50 才足够大,能让这一权衡取舍变得清晰可见。

用通俗的话说:对于每一条记录 r,在准标识符 Q 上与它匹配的其他记录 r’ 的数量必须至少为 k。每条记录都必须能够融入至少 k 减 1 条其他记录之中。importance = c(1,2,3,4,5) 将 Gender(性别)设为最受保护的变量,将 BonusGroup 设为最可舍弃的变量,这是一项价值判断:性别是多个监管机构限制或审慎审查的定价因子(见第二、三章)。

效用代价

解读: 全局风险从0.77%降至0.41%(约47%)。全部抑制都落在 BonusGroup(6.9%)和 ValueGroup(0.44%)上——importance 总是优先用尽代价最低的变量。

注记

对小型数据集或精细地理数据有效。对大型数据集而言,在较小的 k 下抑制率较低,但如上所示,随着 k 增大,抑制率会迅速上升。k-匿名性也难以妥善处理连续变量,也不保护敏感取值(理赔列本身未受触及)。

这正是案例研究中再保险公司问题的一个缩影:即便在 k=50 下,受影响的也只有 ValueGroup 和 BonusGroup——而 Gender、AgeGroup、DensityGroup,恰恰是一位已掌握部分背景信息的再保险公司最有可能已经知道的变量,却完全没有受到这次抑制的影响。这正是为什么单靠 k-匿名性对这一特定接收方而言是一个薄弱的答案。

💬 讨论(3分钟)

k-匿名性并不保护敏感列,只保护将某条记录关联到某个人的能力。

这算是真正的隐私保护,还是虚假的安心?

一种思考方式: 两者皆有可能,取决于敏感列里究竟是什么内容。它切断了“关联”这条链路,这是真正的保护;但对于抑制群组内部的属性推断,它却无能为力(如果一个由50人组成的群组中,所有人都提出过同一类理赔,k-匿名性并不会隐藏这一点)。正是这一确切的缺口,催生了第六章介绍的 l-多样性等扩展方法。

第四部分 — 差分隐私

拉普拉斯机制

在发布统计量前加入经过校准的噪声 (Dwork 等 2006年):

\mathcal{M}(D) = f(D) + \text{Lap}\!\left(\frac{\Delta f}{\varepsilon}\right)

\varepsilon 越小 → 噪声越大 → 隐私性越强,效用越低。

Δf 是敏感度:单条记录被加入或移除时,该统计量最多可能发生的变化,这与本幻灯片前面讨论的理赔列“敏感”含义不同。Lap() 从一个以零为中心、对称的钟形拉普拉斯分布中抽取随机噪声。对于 n 个有界数值的均值而言,敏感度 = (上界-下界)/n——这一个事实,就是接下来两张幻灯片的全部故事。

噪声取决于群体规模,而不只是 \varepsilon

解读: 整体业务组合(n=100,000)在任何 \varepsilon 下噪声都小得几乎看不见。同样的机制、同样的 \varepsilon,应用于第二部分中 n=487 的罕见子群体,在 \varepsilon=0.1 时会带来数年之差的波动。

敏感度按 1/n 缩放。业务组合层面的统计量用差分隐私加以保护几乎是免费的;精细分解的统计量则不然。

当 n = 100,000 时,平均年龄的敏感度约为0.0008——即便 ε = 0.1 也能给出可用的小噪声,这也是为什么整体业务组合的差分隐私估计表,在每一个 epsilon 取值下看起来都没有变化:这并非错误,而正是大 n 所预示的结果。n=487 的群体,正是第二部分聚合问题幻灯片中介绍的“男性、66岁以上、豪华车”这一相同组合。这也是为什么第六章讨论过的2018年美国人口普查重构攻击,在最小的公布地理单元(人口普查区块)上最难防御,而非在州或全国层面——n 越小,敏感度越大,要达到同样的保证就需要更多噪声。

解读 epsilon

ε 整体业务组合(n=100,000) 罕见子群体(n=487) 解读
0.1 可忽略不计 非常大(可达数年之差) 隐私性强;适用于业务组合统计量,不适用于小群体
0.5–1 可忽略不计 大到适中 常见的汇总统计量默认设置
5 可忽略不计 小 即便对中等偏小的群体也可接受
10 可忽略不计 非常小 隐私性弱,接近未受扰动的输出

组合方式很重要:k 次各消耗 ε 的独立查询,总预算为 kε(基础组合方式)。这张表也是案例研究中供应商问题的直接证据——供应商如果只申请一两个业务组合层面的统计量,几乎可以在严格的 epsilon 下免费获得;但如果监管机构后续要求按小子群体(比如按邮编)进行同样的分解,供应商的请求就会落入这张表的右侧一栏,同样的 epsilon 就不再是免费的了。

💬 讨论(4分钟)

为你所在组织下一次公开数据发布设定 epsilon。

ε = 0.5(隐私性强,噪声大)还是 ε = 5(隐私性弱,更实用)?由什么决定?

一种思考方式: 起决定作用的更多是 n,而非某条固定规则。对于本章示例这样的业务组合层面统计量,\varepsilon=0.5 本身已经几乎不带来代价,因此没有太多理由去接受 \varepsilon=5 这一更弱的保证。真正的权衡取舍,只有在统计量是基于一个小群体计算时,才会开始显现。

第五部分 — 合成数据

合成数据的理想属性

评判合成数据生成器通常依据三项属性,这三者并不会自动同步提升 (Jordon 等 2022年):

  • 保真度 — 合成分布是否在边际与联合意义上都与真实分布相似?
  • 效用 — 它是否真正支持下游任务,而不只是看起来相似?
  • 隐私性 — 发布它是否会泄露关于具体真实个体的信息?

一个记住了训练数据的生成器,会在保真度与效用上得分完美,却完全无法满足隐私性。接下来的检验会依次检验这三项属性。

这一框架说明了为什么保真度检验(边际分布、系数)并非评估的终点——一份合成数据集可能在统计意义上看起来相似,却依然无法用于实际目的,或依然会泄露具体个体。这一顺序在教学上也有意义:一份连保真度都达不到的数据集,不值得再进一步检验效用或隐私性。

使用 synthpop 生成

拟合一系列条件模型,逐一变量进行(默认使用 CART),从拟合的序列中抽样生成新的合成记录,而非重新抽样真实记录。

CART 代表分类与回归树,一种通过反复依据其他变量将数据划分为不同群组来预测每个变量的方法。关键在于,CART 是从匹配叶节点内实际观测到的取值中抽取每一个合成数值,而非做平滑或插值——这一个事实,同时解释了良好的保真度结果,以及几张幻灯片之后出现的 NNDR 尖峰。在合成之前,会留出2,000条真实记录作为留出集,专门用于之后检验泛化能力。

保真度:边际分布

在年龄、密度和车辆价值上,合成分布与真实分布高度吻合。

Density 和 Value 是按 log(1+x) 而非原始尺度绘制的,因为二者都存在严重的右偏(密集城区和豪华车构成一条长尾)——按原始尺度绘制,几乎所有记录都会被压缩成零附近的一根尖峰,任何真正的保真度差距都会被掩盖其中。使用 log1p 而非普通的 log,是因为它在 x=0 处依然有定义,这一点很重要,因为部分记录的 Density 或 Value 接近于零。

评估效用:TSTR

以合成数据训练、以真实数据检验:在合成数据上训练一个模型,在合成过程从未见过的真实记录上评估它。这检验的是下游使用者真正会做的事情,而不仅仅是外观相似性。

模型训练所用数据 在2,000条真实留出记录上的 AUC
真实数据 0.728
合成数据 0.729

差距可忽略不计,甚至方向相反。 完全基于合成数据构建的模型,在真实的未来业务上的表现,与基于真实数据(即合成数据本应保护的那份数据)构建的模型一样好。

这直接回答了案例研究中再保险公司的问题:他们希望确信,一个基于合成数据构建的定价模型,在真实的未来业务上确实可用。这里的 AUC 差距(0.001)是本章中支持“合成数据可以替代真实记录级数据完成这一特定用途”这一结论的最有力证据。相比之下,前面检验的系数一致性,只是一种更弱的、仅停留在外观相似层面的检验——TSTR 才是直接检验。

评估隐私性:NNDR

\text{NNDR} = \frac{d(\text{合成}_i, \text{最近真实记录})}{d(\text{合成}_i, \text{次近真实记录})}

接近1 = 并非复制。接近0 = 存在记忆风险。

在接近0处确实出现了一个真实的尖峰:约4%的抽样记录(500条中的20条)在 Age/Density/Value 上与某条真实记录完全匹配。这并非记忆现象——Density 在8,000条记录中只有471个不同取值,因此 CART 的叶节点重抽样有可能巧合地重现出某一条真实组合。分类列(Group1、Bonus)通常仍然不同。

重要

数值列上的 NNDR 只是其中一项检验。一次完整的评估还应检验成员推断(攻击者能否判断某条具体记录是否曾用于训练模型?)和属性推断(攻击者能否从合成数据中猜出某人的敏感字段?)(Jordon 等 2022年)。

这正是前面 synthpop 那张幻灯片中提到的“从实际观测数据生成每一个取值”这一特性的直接体现。这一尖峰是一个真实的、可以解释的发现,既不是漏洞,也不应被简单地淡化为“没有风险”——它恰恰是成员推断检验存在的意义所在。这也是为什么案例研究给再保险公司的答案中,把这一点列为附加检验事项,而非一份“全部安全”的结论。

💬 讨论(4分钟)

NNDR 接近1,说明大多数合成记录并非真实记录的复制品——但仍有一小部分,在检验的数值列上完全匹配。

这是否改变了该数据集是否可以安全发布的判断?你还想检查什么?

一种思考方式: 既不应自动叫停,也不能视为“全部安全”。在所检验的变量上出现4%的完全匹配率,意味着在发布之前应当进行成员推断检验,而不是径直叫停发布——这与下方提示框所得出的“还需进一步检验”这一结论是一致的。

小结

按生命周期阶段划分的管控措施

阶段 关键管控措施
收集 最小必要原则,记录法律依据
存储 假名化、加密、基于角色的访问控制
分析 目的限制,在分析师访问前进行 k-匿名化/差分隐私处理
输出/共享 仅提供汇总数据,加入差分隐私噪声,签订数据共享协议
保留 自动删除,安全销毁

案例研究揭晓:回答这三个问题

  1. 哪一位接收方可以获得 k-匿名化数据? 可以说没有一位——这并非因为 k-匿名性有缺陷,而是因为对这三份申请而言它都用错了工具。在它原本可能适用的地方,再保险公司的背景信息又进一步削弱了它:本章 k=50 的结果让 Gender/AgeGroup/DensityGroup 完全未受影响,而这恰恰是一家长期合作的分保伙伴最有可能已经知道的信息。
  2. 定价团队需要合成数据吗? 不需要——更简单的答案是只需治理措施:用途限制与基于角色的访问控制。他们是内部团队,本已受信任,且无论用什么数据训练,都会针对生产环境的真实数据进行验证。
  3. 供应商只需要汇总统计量,是否排除了两种技术? 是的。k-匿名性和合成数据都是为保护文件而生,而供应商从未收到过文件。差分隐私是三者中唯一相关的技术。

简而言之: 再保险公司 → 合成数据(TSTR:AUC 0.728 对 0.729)。内部团队 → 仅需治理措施。供应商 → 差分隐私。三位接收方,三种不同的工具。

这正是以案例研究开篇所带来的回报:到本章结束时,“应该使用哪种 PET”已经变成了“这取决于接收方,而这里是你展示论证过程的方式”——这正是第八章权衡取舍讨论,将要求学生在公平性、可解释性与隐私性三者之间再次运用的能力。

总结

  • 即便在大型“匿名化”数据集中,重新识别风险依然真实存在
  • k-匿名性:降低可识别性,不保护敏感取值,一旦 k 大到有实际意义,就会损失效用
  • 差分隐私:具有数学保证,能很好地随 n 扩展——同样的 \varepsilon,对小子群体的代价远高于对大型业务组合
  • 合成数据(synthpop/CART):从保真度、效用(TSTR)与隐私性(NNDR)三方面评估——三项表现均良好,但存在一个真实、可解释的少数匹配注意事项
  • 没有任何单一技术本身是充分的,也没有任何单一技术适用于所有接收方——需要与接收方相匹配的分层管控措施
