学习目标

  • 通过识别准标识符并衡量重新识别风险,对一个表格型数据集进行基本的隐私风险评估。
  • 在真实数据上应用 k-匿名性并评估重新识别风险。
  • 为差分隐私统计量实现拉普拉斯机制。
  • 生成并评估合成数据,作为发布真实记录的替代方案。
  • 衡量每种技术的隐私—效用权衡取舍,并为数据生命周期的每个阶段识别恰当的管控措施。

从原则到实践

第六章介绍了一个数据集为什么带有重新识别风险,以及哪一种隐私增强技术(PET)能够应对这一风险。将这一选择转化为一套可运行的流程,无论在哪个领域,都遵循相同的步骤:

  1. 识别数据集中的准标识符(单独并不具有识别性、但组合起来可揭示某人身份的变量),并据此评估重新识别风险。
  2. 选择与使用场景相匹配的隐私增强技术,对微观数据发布使用抑制/泛化(k-匿名性),对汇总统计量使用噪声注入(差分隐私),或对需要真实感但非真实记录的场景使用合成数据生成。
  3. 将该技术应用于数据集。
  4. 衡量权衡取舍,将效用损失(如下游统计量或模型性能的偏差)与剩余披露风险相权衡,而非孤立看待。
  5. 判断该权衡取舍对预期的发布或用途而言是否可接受,并记录这一决策。

本讲座将在一个实例上,完整展开第3至5步,因此上述每一步都会有一个具体的实现可供参照。

注记案例研究:如何向三个不同的接收方发布保单数据

该保险公司的数据治理政策要求,任何对外发布保单级数据的行为,都必须经数据治理主管审批,并附有正式的风险评估,这正是第六章所介绍的隐私影响评估(DPIA)流程。目前同时收到了三份申请,每一份的风险状况都不相同:

  1. 一家再保险公司,正在为明年的比例分保合约续保定价,希望获得保单级的风险暴露与理赔数据,以构建自己独立的定价模型。它是一个长期合作的业务伙伴,曾在往年的分保合约中审计过部分相同的保单持有人,因此可能已经掌握了关于该业务组合中有哪些人的部分背景信息,而不是一个从零开始的完全外部者。
  2. 保险公司自己的精算定价团队,正在构建明年的费率模型,需要行为上与真实业务组合相似的数据,包括真实的相关关系、真实的罕见组合,但该模型无论如何都会针对生产环境的真实数据进行验证,因此并不严格需要真实的个体记录。
  3. 一家行业基准测试供应商,正在为监管机构的市场行为审查构建一个全市场费率比较工具,只需要按定价因子划分的汇总统计量,完全不需要个体保单记录。

数据治理主管必须针对每一位接收方,决定哪种隐私增强技术(如果需要的话)是相称的,并在任何数据离开公司之前将该决定记录在案。

在学习本章的过程中,请思考以下问题:

  • 在这三位接收方中,哪一位可以被正当地提供 k-匿名化数据,哪一位则需要更强的技术?再保险公司所掌握的部分背景信息,是否会改变你的答案,考虑到第六章已经指出,并非所有接收方都是毫无背景知识的外部者?
  • 定价团队并不严格需要真实记录,只需要真实感的数据。这是否意味着必须使用合成数据,还是说,考虑到该团队是内部团队,存在一个更简单、更经济的答案?
  • 供应商只需要汇总统计量,完全不需要记录级文件。这是否意味着本章三种技术中,只有其中一种才真正适用于这一请求?

在本章将三种技术都应用于该数据集、并得到实际测量的数字之后,我们会回到这一案例研究,用数据本身来回答这些问题,而不只是凭直觉。

重新识别风险评估

准标识符

准标识符 是指那些本身并非直接标识符、但通过与外部数据交叉比对、组合后可唯一识别个人的变量。

在车险数据中,可能的准标识符包括:

变量 为什么是准标识符
Gender 与其他变量组合后,能大幅缩小群体范围
Age(或 AgeGroup) 最具识别性的变量之一
DensityGroup 车辆停放地区的人口密度,是邮编/位置的代理变量,可用于交叉比对
ValueGroup 车辆价值缩小候选范围,在极端值处尤为明显
BonusGroup 无赔款折扣等级(基于无理赔年数的折扣档位),在同一年龄组内缩小候选范围

使用 sdcMicro 衡量重新识别风险

sdcMicro (Templ 2017年) 实现了标准的统计披露控制方法。关键指标是个体重新识别风险,即某条具体记录能够被匹配到一个真实个体的概率。全局风险 则是对整个数据集这一指标的汇总,大致相当于可能被重新识别的记录所占的总体比例。

这一风险是如何估计的。 对每条记录,sdcMicro 首先统计其样本频数 f_k:数据集中(包括该记录本身)在准标识符取值组合上与其完全相同的记录数。若某条记录在准标识符上是唯一的,则 f_k = 1。

如果该文件就是整个总体,而非从更大总体中抽取的样本,那么在 f_k 条无法区分的记录中,正确猜中目标身份的概率就是

r_k = \frac{1}{f_k}.

sdcMicro 的默认估计方法是对这一思路的推广:由于已发布的文件往往只是更大总体的一个样本,它借助一个超总体模型来刻画样本频数 f_k 与未知的总体频数之间的关系,假设样本计数与总体计数之间的关系服从负二项分布 (Franconi 和 Polettini 2004年)。下文调用 createSdcObj() 时并未提供抽样权重,因此该文件实际上被当作总体处理,估计结果会趋近于上述简单的 1/f_k 直觉:取值组合越罕见,风险就相应越高。

这与下一节存在直接的数学联系。k-匿名性要求每个等价类至少包含 k 条记录,即对每条记录都有 f_k \geq k,这恰好等价于保证 r_k \leq 1/k。

全局风险与预期重新识别数量。 将每条记录的个体风险 r_k 相加,即得到预期重新识别数量:若攻击者尝试依据准标识符对每一条记录进行重新识别,预期能够成功匹配的记录数。全局风险则是将这一总量表示为数据集的一个比例,即预期重新识别数量除以记录总数。

解读这一风险

由于数据集规模较大(100,000条记录),且准标识符已被归入较宽泛的分组,因此全局风险较低。

但这低估了真实风险。在实践中:

  • 接收这份数据的再保险公司,可能已经知道业务组合中包含哪些保单持有人(持有保单的个人)。他们只需核实细节,而不必从零开始识别
  • 掌握车辆登记数据的攻击者,可以交叉比对 ValueGroup 和 AgeGroup,大幅缩小候选范围
  • 即便在一个大型数据集中,罕见的组合(如“66岁以上、密集城区、豪华车、低折扣等级”)也具有很高的重新识别可能性

聚合问题

单独来看,每一个准标识符都是无害的:

  • 知道某人是男性,不具有识别性
  • 知道某人属于66岁以上年龄组,不具有识别性
  • 知道某人拥有一辆豪华车,不具有识别性

k-匿名性

使用 sdcMicro 应用 k-匿名性

上文的准标识符在数据准备阶段就已经被泛化为分组(精确年龄归入年龄段,精确密度归入密度段,等等)。如果每一种至少被一条记录共享的准标识符取值组合,总共至少被 k 条记录共享,即每条记录的等价类都包含其自身在内至少 k - 1 条其他记录,则该数据集满足 k-匿名性。仅凭泛化,仍会留下许多远低于下文将要施加的 k = 50 的等价类,其中一些群组小到只有一条记录,正如上文“最小的十个准标识符群组”表所示。

本节在现有分组的基础上,应用局部抑制,即对规模小于 k 的群组,将其最具识别性的准标识符取值抑制(设为 NA),使每一个剩余群组的规模都达到 k。这里选用 k = 50,大于教科书式的最小值 k = 5,正是为了让抑制及其效用代价变得清晰可见,而非微不足道。100,000条记录中只有102条低于 k = 5,因此 k = 5 这一遍处理几乎不会触及数据集。

局部抑制如何决定要抑制哪些取值。 对于每一条等价类规模小于 k 的记录,localSuppression() 会寻找需要设为缺失值的最少数量的准标识符取值,使该记录所在的等价类规模达到 k,并依据 importance 向量决定优先牺牲哪些变量。数值越小,该变量越受保护、越不易被抑制;数值越大,该变量越优先被抑制。下方代码按照 keyVars 的顺序,将 Gender(性别)设为最受保护的变量(importance = 1),将 BonusGroup 设为最可舍弃的变量(importance = 5)。这是一项价值判断:性别是多个监管机构限制或审慎审查的定价因子(见第二、三章),因此即便在需要抑制某条记录时会因此损失更多 BonusGroup 信息,也值得优先加以保护。

差分隐私

拉普拉斯机制

差分隐私 (Dwork 等 2006年) 在统计量发布前加入经过校准的噪声,确保输出结果几乎不透露任何关于某一具体记录的信息。

对于全局敏感度为 \Delta f(某单条记录被加入或移除时,该统计量可能发生的最大变化,这与本章其他地方所讨论的“敏感”数据是不同的含义)的数值函数 f(D),拉普拉斯机制 发布的结果为:

\mathcal{M}(D) = f(D) + \text{Lap}\!\left(\frac{\Delta f}{\varepsilon}\right)

这里的 \varepsilon(epsilon)是隐私预算:\varepsilon 越小,加入的噪声越多,隐私性越强;\varepsilon 越大,加入的噪声越少,结果越准确但隐私性越弱。Lap() 本身从一个以零为中心、对称的钟形拉普拉斯分布中抽取噪声。

我们从零开始实现这一机制,以建立直观理解。

差分隐私辅助函数 
# Draw a single noise value from Laplace(0, sensitivity/epsilon) using the
# inverse-CDF (quantile) method: if u ~ Uniform(0,1), then
# -b * sign(u - 0.5) * log(1 - 2|u - 0.5|) is Laplace(0, b) distributed.
laplace_noise <- function(sensitivity, epsilon, n = 1) {
  scale <- sensitivity / epsilon
  u <- runif(n) - 0.5
  -scale * sign(u) * log(1 - 2 * abs(u))
}

# Differentially private mean of x, where x is known to lie in [lower, upper].
# Sensitivity of a mean over n bounded values is (upper - lower) / n: swapping
# one record can move the mean by at most one value's range, divided by n.
# This is the key reason DP noise shrinks as the group being averaged grows.
dp_mean <- function(x, lower, upper, epsilon) {
  n <- length(x)
  sensitivity <- (upper - lower) / n
  true_mean <- mean(x, na.rm = TRUE)
  true_mean + laplace_noise(sensitivity, epsilon)
}

# Differentially private count of records satisfying `condition`.
# Sensitivity of a count is 1: adding or removing one record changes the
# count by at most 1, regardless of n, so count noise does NOT shrink with n.
dp_count <- function(x, condition, epsilon) {
  true_count <- sum(condition(x), na.rm = TRUE)
  round(true_count + laplace_noise(sensitivity = 1, epsilon = epsilon))
}

# Differentially private proportion: release the count with DP, then divide
# by the (public, non-private) sample size n. Because count noise has a fixed
# scale, dividing by a small n can swing the resulting proportion a lot.
dp_proportion <- function(x, condition, epsilon) {
  n <- length(x)
  dp_count(x, condition, epsilon) / n
}

重要

单次差分隐私发布会消耗隐私预算 ε。如果从同一数据集发布多项统计量,隐私预算必须加以组合。连续的发布会使风险成倍累积。对于 k 次各消耗 \varepsilon 的独立查询,总预算为 k\varepsilon(基础组合方式)。更精细的核算方法(如 Rényi 差分隐私)则能给出更紧的边界。

合成数据

使用 synthpop 生成合成保险数据

synthpop (Nowok 等 2016年) 通过拟合一系列条件模型(逐一变量地进行、并以此前已合成的变量为条件),生成合成数据(在统计意义上与真实数据相似、但不对应任何真实个体实际记录的人工记录)。默认情况下,它使用 CART(分类与回归树,一种通过反复依据其他变量将数据划分为不同群组来预测每个变量的方法)。

合成数据的理想属性。 评判合成数据生成器通常依据三项属性,这三者并不会自动同步提升 (Jordon 等 2022年):

  • 保真度:合成数据的分布,在边际意义上(每个变量单独而言)以及联合意义上(变量之间的相互关系),与真实数据的分布有多接近。下文的边际分布检验与汇总统计量检验直接检验这一点。
  • 效用:合成数据是否真正支持其原本要服务的下游任务,而不只是看起来相似。系数一致性检验,以及更直接的以合成数据训练、以真实数据检验(TSTR)检验,检验的正是这一点。
  • 隐私性:发布这份合成数据,是否会泄露关于具体真实个体的信息。下文的最近邻距离检验检验的是这一点,不过完整的隐私评估还需要成员推断与属性推断检验,详见下文进一步讨论。

这三项属性彼此之间存在权衡。一个记住了训练数据的生成器,会在保真度和效用上得分完美,却完全无法满足隐私性。反之,一个加入了过多噪声或正则化、以至于任何真实记录都无法被推断出来的生成器,隐私性表现良好,但保真度和效用都会很差。下文按照数据托管方通常需要满足这些要求的顺序,依次检验这三项属性:先保真度,再效用,最后隐私性——一份连基本相似度都达不到的合成数据集,并不值得再进一步检验。

评估保真度:边际分布

合成数据的边际分布与真实数据是否匹配?Age(年龄)按原始尺度绘制,而 Density(车辆停放地区的人口密度)和 Value(车辆价值)则按 log(1 + x) 尺度绘制。这两个变量都存在严重的右偏:大多数保单持有人居住在中低密度地区、驾驶中等价位的车辆,但密集城区和豪华车构成了一条远远拖出主体分布之外的长尾。若按原始尺度绘制密度图,几乎所有记录都会被压缩成零附近的一根细尖峰,分布中段和尾部的信息几乎完全不可见,任何真正重要的真实数据与合成数据之间的差异,也都会被淹没在这根尖峰之中。log1p() 变换,即 \log(1 + x) 而非普通的 \log(x),能够压缩这条长尾,同时在 x = 0 处依然有定义(普通的 \log(0) 为 -\infty),这一点在本例中很重要,因为部分记录的 Density 或 Value 取值为零或接近零。

评估效用:以合成数据训练、以真实数据检验(TSTR)

系数一致性检验的是合成数据是否在外观上近似真实数据,并未回答数据使用者真正关心的问题:如果用这份合成数据来构建一个生产模型,它在真实的、未来的记录上表现如何?检验这一点的标准方法是以合成数据训练、以真实数据检验(TSTR):在合成数据上训练一个模型,然后在合成过程从未见过的真实记录上评估它,此处即为前文留出的2,000条 df_real_holdout 记录。我们将其与自然基准进行比较:同一个模型在真实训练数据上拟合,并在同一份真实留出集上评估。

代码 
# Area under the ROC curve (AUC), computed from ranks rather than a package:
# AUC = P(a random positive scores higher than a random negative), which the
# sum of ranks among the positive cases estimates directly (Mann-Whitney U).
auc_manual <- function(pred, actual) {
  n1 <- sum(actual == 1)
  n0 <- sum(actual == 0)
  r  <- rank(pred)
  (sum(r[actual == 1]) - n1 * (n1 + 1) / 2) / (n1 * n0)
}

holdout_actual <- as.integer(df_real_holdout$Numtppd > 0)

# Same two models fitted above (model_real on real data, model_syn on
# synthetic data), now scored on real records neither model was trained on
pred_from_real_model <- predict(model_real, newdata = df_real_holdout, type = "response")
pred_from_syn_model  <- predict(model_syn,  newdata = df_real_holdout, type = "response")

tibble(
  `Model trained on` = c("Real data", "Synthetic data"),
  `AUC on real holdout` = c(
    round(auc_manual(pred_from_real_model, holdout_actual), 4),
    round(auc_manual(pred_from_syn_model,  holdout_actual), 4)
  )
) %>%

评估隐私性:最近邻距离

一个逐字复制真实记录的合成数据集,不提供任何隐私保护。最近邻距离比(NNDR)衡量的是合成记录与真实记录的接近程度:

\text{NNDR} = \frac{d(\text{合成记录}_i, \text{最近真实记录})}{d(\text{合成记录}_i, \text{次近真实记录})}

NNDR 接近1,意味着最近的真实记录并不比次近的真实记录更近,因此该合成记录并非一次复制。NNDR 接近0,则提示存在记忆现象。

为什么是比值,而不是直接看到最近真实记录的距离。 仅凭原始距离来判断是有误导性的,因为它没有考虑局部密度。在数据密集的区域(常见的 Age、Density、Value 组合),任何一个附近的点,包括一条完全没有复制任何内容的合成记录,都会自然地与某条真实记录距离很近,原因仅仅是那一区域的真实记录本就密集。这并不是泄露,只是几何特性使然。除以次近真实记录的距离,正是为了消除这一影响:在密集区域中,最近和次近的真实记录彼此都很近、距离也大致相当,因此比值会保持在接近1的水平——这说明该合成点并未可疑地依附于某一条具体记录,它只是恰好落在分布中较为密集的一部分,这本就是预期之中的。反之,如果一条合成记录实际上是对某一条具体真实记录的近似复制,它到最近邻的距离会趋近于零,而到次近邻的距离仍保持在该区域正常的尺度上,于是比值就会趋近于0。这正是那种“并非只是附近有数据,而是发生了某种具体情况”的、经过密度归一化处理后的信号。

不过,NNDR 终归是一项范围狭窄的检验:它只检验距离计算中所包含的具体数值列(下文为 Age、Density、Value,不包括分类列)上是否存在精确或近似精确的几何邻近关系。它无法说明成员推断(攻击者能否在不存在任何单条合成记录可疑接近的情况下,例如借助汇总统计特征,判断某个具体真实个体是否曾出现在训练数据中?)或属性推断(攻击者能否在没有任何记录级匹配的情况下,仅凭整体合成数据推断出某人的某个敏感属性?)。它是针对“记忆现象”这一种特定失效模式的、廉价而有用的初步诊断工具,而非像差分隐私的数学边界那样的隐私保证。

注记案例研究揭晓:回答开篇提出的三个问题

问题一:哪一位接收方可以被正当地提供 k-匿名化数据?再保险公司所掌握的部分背景信息,是否会改变你的答案?

可以说,三者都不适合——但这并非因为 k-匿名性本身有缺陷,而是因为对这三份具体的申请而言,它都不是恰当的工具。再保险公司需要真实感的记录级数据来构建独立模型,而 k-匿名性只会降低这类数据的质量,而非提供它;内部团队根本不需要一份被降质处理过的文件;供应商则完全不需要任何文件。而在 k-匿名性原本可能适用的情形下,背景知识确实会改变答案:本章自己在 k=50 下的结果表明,Gender(性别)、AgeGroup(年龄组)、DensityGroup(密度组)——恰恰是一家在往年分保合约中接触过部分保单持有人的再保险公司,最有可能已经掌握的变量——完全未受抑制的影响,因此“隐藏在 k 个他人之中”这一论证,对这一特定接收方而言,要比对一个毫无背景知识的外部者弱得多。

问题二:定价团队需要真实感(而非真实)的数据,这是否意味着必须使用合成数据,还是存在更简单的答案?

更简单的答案是:根本不需要任何隐私增强技术,只需要治理措施。定价团队身处内部,已经受保密义务约束,且无论用什么数据训练,其模型最终都会针对生产环境中的真实数据进行验证。将合成的精力花在一个并不需要它、且从组织内部已有数据中也得不到任何额外隐私收益的接收方身上,是一种用错了地方的努力。下文生命周期管控表中“分析/建模”一行所列的用途限制与基于角色的访问控制,才是相称的管控措施。

问题三:供应商只需要汇总统计量,这是否排除了本章三种技术中的两种?

是的。k-匿名性和合成数据都是为保护文件而生,而供应商从未收到过文件。这样一来,差分隐私就成了三种技术中唯一相关的选择,本章自己的结果也表明,在这一业务组合的规模下,强隐私性(较小的 \varepsilon)对于一个业务组合层面的统计量而言,几乎不会带来任何准确性代价,只要监管机构日后不要求按更小的子群体进行更精细的分解。

简而言之: 再保险公司适用合成数据(TSTR:AUC 0.728 对 0.729,仍需受限于前文提到的成员推断这一附加检验),内部团队仅需治理措施,供应商适用差分隐私。三位接收方,三种不同的工具,而非用同一种技术一概而论。

小结

  • 重新识别风险 即便在大型的“匿名化”数据集中依然真实存在。准标识符的组合能够唯一识别出罕见群体,而同样的风险评估工作流程(识别准标识符 → 选择匹配的隐私增强技术 → 应用 → 衡量权衡取舍 → 决策)也可迁移至其他领域。
  • 通过局部抑制实现的k-匿名性降低了可识别性,但并不保护敏感取值,而且一旦 k 大到足以迫使真正的抑制发生(而不只是教科书式的最小值 k = 5),效用代价就会迅速上升。
  • 差分隐私 提供数学上的保证,并能很好地适应大型数据集:同样的 \varepsilon,对100,000条记录的汇总统计量几乎没有影响,但对一个小型子群体却可能造成明显失真,因为敏感度按 1/n 缩放。拉普拉斯机制对汇总统计量而言实现起来很直接。
  • 来自 synthpop(CART)的合成数据在边际分布和模型系数上取得了良好的保真度,一个在其上训练的模型在留出的真实记录上(TSTR)的表现也几乎与在真实数据上训练的模型一样好,NNDR 证据也表明真实记录并未被复制。
  • 没有任何单一技术本身是充分的——需要在整个数据生命周期中采取分层管控措施。

## 从原则到实践

第六章介绍了一个数据集*为什么*带有重新识别风险,以及*哪一种*隐私增强技术(PET)能够应对这一风险。将这一选择转化为一套可运行的流程,无论在哪个领域,都遵循相同的步骤:

1. **识别数据集中的准标识符**(单独并不具有识别性、但组合起来可揭示某人身份的变量),并据此评估重新识别风险。
2. **选择与使用场景相匹配的隐私增强技术**,对微观数据发布使用抑制/泛化(k-匿名性),对汇总统计量使用噪声注入(差分隐私),或对需要真实感但非真实记录的场景使用合成数据生成。
3. **将该技术应用**于数据集。
4. **衡量权衡取舍**,将效用损失(如下游统计量或模型性能的偏差)与剩余披露风险相权衡,而非孤立看待。
5. **判断该权衡取舍对预期的发布或用途而言是否可接受**,并记录这一决策。

本讲座将在一个实例上,完整展开第3至5步,因此上述每一步都会有一个具体的实现可供参照。

# 重新识别风险评估

## 准标识符

**准标识符** 是指那些本身并非直接标识符、但通过与外部数据交叉比对、组合后可唯一识别个人的变量。

在车险数据中,可能的准标识符包括:

| 变量 | 为什么是准标识符 |
|----------|---------------------------|
| Gender | 与其他变量组合后,能大幅缩小群体范围 |
| Age(或 AgeGroup) | 最具识别性的变量之一 |
| DensityGroup | 车辆停放地区的人口密度,是邮编/位置的代理变量,可用于交叉比对 |
| ValueGroup | 车辆价值缩小候选范围,在极端值处尤为明显 |
| BonusGroup | 无赔款折扣等级(基于无理赔年数的折扣档位),在同一年龄组内缩小候选范围 |

## 使用 `sdcMicro` 衡量重新识别风险

`sdcMicro` [@templ2017statistical] 实现了标准的统计披露控制方法。关键指标是**个体重新识别风险**,即某条具体记录能够被匹配到一个真实个体的概率。**全局风险** 则是对整个数据集这一指标的汇总,大致相当于可能被重新识别的记录所占的总体比例。

**这一风险是如何估计的。** 对每条记录,`sdcMicro` 首先统计其**样本频数** $f_k$:数据集中(包括该记录本身)在准标识符取值组合上与其完全相同的记录数。若某条记录在准标识符上是唯一的,则 $f_k = 1$。

如果该文件就是整个总体,而非从更大总体中抽取的样本,那么在 $f_k$ 条无法区分的记录中,正确猜中目标身份的概率就是

$$
r_k = \frac{1}{f_k}.
$$

`sdcMicro` 的默认估计方法是对这一思路的推广:由于已发布的文件往往只是更大总体的一个样本,它借助一个超总体模型来刻画样本频数 $f_k$ 与未知的总体频数之间的关系,假设样本计数与总体计数之间的关系服从负二项分布 [@franconi2004individual]。下文调用 `createSdcObj()` 时并未提供抽样权重,因此该文件实际上被当作总体处理,估计结果会趋近于上述简单的 $1/f_k$ 直觉:取值组合越罕见,风险就相应越高。

这与下一节存在直接的数学联系。**k-匿名性要求每个等价类至少包含 $k$ 条记录**,即对每条记录都有 $f_k \geq k$,这恰好等价于保证 $r_k \leq 1/k$。

**全局风险与预期重新识别数量。** 将每条记录的个体风险 $r_k$ 相加,即得到**预期重新识别数量**:若攻击者尝试依据准标识符对每一条记录进行重新识别,预期能够成功匹配的记录数。全局风险则是将这一总量表示为数据集的一个比例,即预期重新识别数量除以记录总数。

```{r sdc-object}
#| code-fold: true

  as.data.frame()
```

## 解读这一风险

由于数据集规模较大(100,000条记录),且准标识符已被归入较宽泛的分组,因此全局风险较低。

- 接收这份数据的再保险公司,可能**已经知道**业务组合中包含哪些保单持有人(持有保单的个人)。他们只需核实细节,而不必从零开始识别

## 聚合问题

单独来看,每一个准标识符都是无害的:

- 知道某人是男性,不具有识别性
- 知道某人属于66岁以上年龄组,不具有识别性
- 知道某人拥有一辆豪华车,不具有识别性

# k-匿名性

## 使用 `sdcMicro` 应用 k-匿名性

上文的准标识符在数据准备阶段就已经被**泛化**为分组(精确年龄归入年龄段,精确密度归入密度段,等等)。如果每一种至少被一条记录共享的准标识符取值组合,总共至少被 $k$ 条记录共享,即每条记录的等价类都包含其自身在内至少 $k - 1$ 条其他记录,则该数据集满足 **k-匿名性**。仅凭泛化,仍会留下许多远低于下文将要施加的 $k = 50$ 的等价类,其中一些群组小到只有一条记录,正如上文“最小的十个准标识符群组”表所示。

本节在现有分组的基础上,应用**局部抑制**,即对规模小于 $k$ 的群组,将其最具识别性的准标识符取值抑制(设为 `NA`),使每一个剩余群组的规模都达到 $k$。这里选用 $k = 50$,大于教科书式的最小值 $k = 5$,正是为了让抑制及其效用代价变得清晰可见,而非微不足道。100,000条记录中只有102条低于 $k = 5$,因此 $k = 5$ 这一遍处理几乎不会触及数据集。

**局部抑制如何决定要抑制哪些取值。** 对于每一条等价类规模小于 $k$ 的记录,`localSuppression()` 会寻找需要设为缺失值的最少数量的准标识符取值,使该记录所在的等价类规模达到 $k$,并依据 `importance` 向量决定优先牺牲哪些变量。**数值越小**,该变量越受保护、越不易被抑制;**数值越大**,该变量越优先被抑制。下方代码按照 `keyVars` 的顺序,将 `Gender`(性别)设为最受保护的变量(`importance = 1`),将 `BonusGroup` 设为最可舍弃的变量(`importance = 5`)。这是一项价值判断:性别是多个监管机构限制或审慎审查的定价因子(见第二、三章),因此即便在需要抑制某条记录时会因此损失更多 `BonusGroup` 信息,也值得优先加以保护。

```{r kanonymity}
#| code-fold: true
#| code-summary: "应用 k = 50 匿名化"

# k = 50 (not the textbook-minimum k = 5) so the suppression is large enough to see
sdc_k50 <- localSuppression(sdc, k = 50, importance = c(1, 2, 3, 4, 5))

risk_after <- sdc_k50@risk$global   # global risk after suppression, for comparison to `sdc` (before)

```

# 差分隐私

## 拉普拉斯机制

差分隐私 [@dwork2006calibrating] 在统计量发布前加入经过校准的噪声,确保输出结果几乎不透露任何关于某一具体记录的信息。

对于全局**敏感度**为 $\Delta f$(某单条记录被加入或移除时,该统计量可能发生的最大变化,这与本章其他地方所讨论的“敏感”数据是不同的含义)的数值函数 $f(D)$,**拉普拉斯机制** 发布的结果为:

$$\mathcal{M}(D) = f(D) + \text{Lap}\!\left(\frac{\Delta f}{\varepsilon}\right)$$

这里的 $\varepsilon$(epsilon)是**隐私预算**:$\varepsilon$ 越小,加入的噪声越多,隐私性越强;$\varepsilon$ 越大,加入的噪声越少,结果越准确但隐私性越弱。`Lap()` 本身从一个以零为中心、对称的钟形拉普拉斯分布中抽取噪声。

我们从零开始实现这一机制,以建立直观理解。

```{r dp-functions}
#| code-fold: true
#| code-summary: "差分隐私辅助函数"

# Draw a single noise value from Laplace(0, sensitivity/epsilon) using the
# inverse-CDF (quantile) method: if u ~ Uniform(0,1), then
# -b * sign(u - 0.5) * log(1 - 2|u - 0.5|) is Laplace(0, b) distributed.
laplace_noise <- function(sensitivity, epsilon, n = 1) {
  scale <- sensitivity / epsilon
  u <- runif(n) - 0.5
  -scale * sign(u) * log(1 - 2 * abs(u))
}

# Differentially private mean of x, where x is known to lie in [lower, upper].
# Sensitivity of a mean over n bounded values is (upper - lower) / n: swapping
# one record can move the mean by at most one value's range, divided by n.
# This is the key reason DP noise shrinks as the group being averaged grows.
dp_mean <- function(x, lower, upper, epsilon) {
  n <- length(x)
  sensitivity <- (upper - lower) / n
  true_mean <- mean(x, na.rm = TRUE)
  true_mean + laplace_noise(sensitivity, epsilon)
}

# Differentially private count of records satisfying `condition`.
# Sensitivity of a count is 1: adding or removing one record changes the
# count by at most 1, regardless of n, so count noise does NOT shrink with n.
dp_count <- function(x, condition, epsilon) {
  true_count <- sum(condition(x), na.rm = TRUE)
  round(true_count + laplace_noise(sensitivity = 1, epsilon = epsilon))
}

# Differentially private proportion: release the count with DP, then divide
# by the (public, non-private) sample size n. Because count noise has a fixed
# scale, dividing by a small n can swing the resulting proportion a lot.
dp_proportion <- function(x, condition, epsilon) {
  n <- length(x)
  dp_count(x, condition, epsilon) / n
}
```

## 解读 epsilon 的权衡取舍

| ε | 加入平均年龄的噪声(整体业务组合) | 加入平均年龄的噪声(小型子群体,n=487) | 实践解读 |
|---|------------------------|------------------------|--------------------------|
| 0.1 | 可忽略不计 | 非常大(可达数年之差) | 隐私性强,不适用于小群体统计量,但适用于整体业务组合层面 |
| 0.5 | 可忽略不计 | 大 | 用于精细化报告仍有风险 |
| 1 | 可忽略不计 | 适中 | 常见的默认设置,部分监管框架采用 |
| 5 | 可忽略不计 | 小 | 即便对中等偏小的群体也可接受 |
| 10 | 可忽略不计 | 非常小 | 隐私性弱,接近未受扰动的输出 |

::: {.callout-note}
当 $n = 100{,}000$ 条记录时,平均年龄这一统计量的敏感度为 $(100-18)/100{,}000 \approx 0.0008$,因此**大型数据集使差分隐私变得更加实用**:即便在 $\varepsilon = 0.1$ 时,整体业务组合层面的噪声也可忽略不计。但正如上文 $n = 487$ 的子群体所示,一旦 $n$ 较小,同样的保证就会带来真实的精度损失。因此,选择 $\varepsilon$ 与决定发布结果允许多精细,二者无法分开考虑。
:::

:::

# 合成数据

## 使用 `synthpop` 生成合成保险数据

`synthpop` [@nowok2016synthpop] 通过拟合一系列条件模型(逐一变量地进行、并以此前已合成的变量为条件),生成**合成数据**(在统计意义上与真实数据相似、但不对应任何真实个体实际记录的人工记录)。默认情况下,它使用 CART(分类与回归树,一种通过反复依据其他变量将数据划分为不同群组来预测每个变量的方法)。

**合成数据的理想属性。** 评判合成数据生成器通常依据三项属性,这三者并不会自动同步提升 [@jordon2022synthetic]:

- **保真度**:合成数据的分布,在边际意义上(每个变量单独而言)以及联合意义上(变量之间的相互关系),与真实数据的分布有多接近。下文的边际分布检验与汇总统计量检验直接检验这一点。
- **效用**:合成数据是否真正支持其原本要服务的下游任务,而不只是看起来相似。系数一致性检验,以及更直接的以合成数据训练、以真实数据检验(TSTR)检验,检验的正是这一点。
- **隐私性**:发布这份合成数据,是否会泄露关于具体真实个体的信息。下文的最近邻距离检验检验的是这一点,不过完整的隐私评估还需要成员推断与属性推断检验,详见下文进一步讨论。

这三项属性彼此之间存在权衡。一个记住了训练数据的生成器,会在保真度和效用上得分完美,却完全无法满足隐私性。反之,一个加入了过多噪声或正则化、以至于任何真实记录都无法被推断出来的生成器,隐私性表现良好,但保真度和效用都会很差。下文按照数据托管方通常需要满足这些要求的顺序,依次检验这三项属性:先保真度,再效用,最后隐私性——一份连基本相似度都达不到的合成数据集,并不值得再进一步检验。

我们对车险业务组合的一个工作子集进行合成,并留出一部分 `synthpop` 从未见过的**真实**记录。这部分留出集在下文的保真度检验中并不需要用到,但对于后面检验一个在合成数据上训练的模型是否仍适用于全新的真实记录而言,则至关重要。

```{r synthpop-gen}
#| code-fold: true
#| code-summary: "准备合成数据集"

# Use the raw (not banded) variables here, since synthesis should reproduce
# realistic continuous values, not the coarser bands used for k-anonymity
df_synth_pool <- df_raw %>%
  select(Gender, Age, Group1, Bonus, Density, Value,
         Numtppd, Indtppd) %>%
  mutate(
    Group1 = as.numeric(as.character(Group1)),  # factor -> numeric for the CART models
    Bonus  = as.numeric(as.character(Bonus))
  ) %>%
  slice_sample(n = 10000)   # 10k records for speed; full dataset works too

# Hold out 2,000 real records that synthpop will never see. df_synth_input
# (8,000 records) is what gets synthesised; df_real_holdout is kept aside
# purely to test generalisation to unseen real data later (TSTR, below)
holdout_idx     <- sample(nrow(df_synth_pool), 2000)
df_real_holdout <- df_synth_pool[holdout_idx, ]
df_synth_input  <- df_synth_pool[-holdout_idx, ]
```


## 评估保真度:边际分布

合成数据的边际分布与真实数据是否匹配?`Age`(年龄)按原始尺度绘制,而 `Density`(车辆停放地区的人口密度)和 `Value`(车辆价值)则按 **log(1 + x)** 尺度绘制。这两个变量都存在严重的右偏:大多数保单持有人居住在中低密度地区、驾驶中等价位的车辆,但密集城区和豪华车构成了一条远远拖出主体分布之外的长尾。若按原始尺度绘制密度图,几乎所有记录都会被压缩成零附近的一根细尖峰,分布中段和尾部的信息几乎完全不可见,任何真正重要的真实数据与合成数据之间的差异,也都会被淹没在这根尖峰之中。**`log1p()`** 变换,即 $\log(1 + x)$ 而非普通的 $\log(x)$,能够压缩这条长尾,同时在 $x = 0$ 处依然有定义(普通的 $\log(0)$ 为 $-\infty$),这一点在本例中很重要,因为部分记录的 `Density` 或 `Value` 取值为零或接近零。

## 评估效用:以合成数据训练、以真实数据检验(TSTR)

系数一致性检验的是合成数据是否*在外观上近似*真实数据,并未回答数据使用者真正关心的问题:如果用这份合成数据来构建一个生产模型,它在真实的、未来的记录上表现如何?检验这一点的标准方法是**以合成数据训练、以真实数据检验(TSTR)**:在合成数据上训练一个模型,然后在合成过程从未见过的真实记录上评估它,此处即为前文留出的2,000条 `df_real_holdout` 记录。我们将其与自然基准进行比较:同一个模型在真实训练数据上拟合,并在同一份真实留出集上评估。

```{r tstr}
#| results: asis

# Area under the ROC curve (AUC), computed from ranks rather than a package:
# AUC = P(a random positive scores higher than a random negative), which the
# sum of ranks among the positive cases estimates directly (Mann-Whitney U).
auc_manual <- function(pred, actual) {
  n1 <- sum(actual == 1)
  n0 <- sum(actual == 0)
  r  <- rank(pred)
  (sum(r[actual == 1]) - n1 * (n1 + 1) / 2) / (n1 * n0)
}

holdout_actual <- as.integer(df_real_holdout$Numtppd > 0)

# Same two models fitted above (model_real on real data, model_syn on
# synthetic data), now scored on real records neither model was trained on
pred_from_real_model <- predict(model_real, newdata = df_real_holdout, type = "response")
pred_from_syn_model  <- predict(model_syn,  newdata = df_real_holdout, type = "response")

tibble(
  `Model trained on` = c("Real data", "Synthetic data"),
  `AUC on real holdout` = c(
    round(auc_manual(pred_from_real_model, holdout_actual), 4),
    round(auc_manual(pred_from_syn_model,  holdout_actual), 4)
  )
) %>%
  kable(caption = "Train-synthetic-test-real (TSTR): predictive performance on 2,000 held-out real records") %>%
  kable_styling(font_size = 12)
```

**解读这张表。** 两行都是在完全相同的真实留出记录上评分的,因此这是对两种训练数据来源实际能带来什么效果的公平比较。此处两个 AUC 分别为0.728(真实数据)和0.729(合成数据),差距可以忽略不计,甚至方向相反:完全基于合成数据构建的模型,在真实的未来业务上的表现,与基于真实数据(即合成数据本应保护的那份数据)构建的模型几乎一样好。这比单纯的系数一致性更有说服力,因为它直接检验了下游使用者真正会做的事情,而非仅仅是较大差距会说明的问题,即上文的系数一致性可能过于乐观:平均意义上接近的系数,并不能保证模型在需要泛化到从未见过的记录时也具有相近的预测性能。

## 评估隐私性:最近邻距离

一个逐字复制真实记录的合成数据集,不提供任何隐私保护。**最近邻距离比**(NNDR)衡量的是合成记录与真实记录的接近程度:

$$\text{NNDR} = \frac{d(\text{合成记录}_i, \text{最近真实记录})}{d(\text{合成记录}_i, \text{次近真实记录})}$$

NNDR 接近1,意味着最近的真实记录并不比次近的真实记录更近,因此该合成记录并非一次复制。NNDR 接近0,则提示存在记忆现象。

**为什么是比值,而不是直接看到最近真实记录的距离。** 仅凭原始距离来判断是有误导性的,因为它没有考虑局部密度。在数据密集的区域(常见的 `Age`、`Density`、`Value` 组合),*任何*一个附近的点,包括一条完全没有复制任何内容的合成记录,都会自然地与某条真实记录距离很近,原因仅仅是那一区域的真实记录本就密集。这并不是泄露,只是几何特性使然。除以*次*近真实记录的距离,正是为了消除这一影响:在密集区域中,最近和次近的真实记录彼此都很近、距离也大致相当,因此比值会保持在接近1的水平——这说明该合成点并未可疑地依附于某一条具体记录,它只是恰好落在分布中较为密集的一部分,这本就是预期之中的。反之,如果一条合成记录实际上是对某一条具体真实记录的近似复制,它到最近邻的距离会趋近于零,而到次近邻的距离仍保持在该区域正常的尺度上,于是比值就会趋近于0。这正是那种“并非只是附近有数据,而是发生了某种具体情况”的、经过密度归一化处理后的信号。

不过,NNDR 终归是一项范围狭窄的检验:它只检验距离计算中所包含的具体数值列(下文为 `Age`、`Density`、`Value`,不包括分类列)上是否存在精确或近似精确的几何邻近关系。它无法说明**成员推断**(攻击者能否在不存在任何单条合成记录可疑接近的情况下,例如借助汇总统计特征,判断某个具体真实个体是否曾出现在训练数据中?)或**属性推断**(攻击者能否在没有任何记录级匹配的情况下,仅凭整体合成数据推断出某人的某个敏感属性?)。它是针对“记忆现象”这一种特定失效模式的、廉价而有用的初步诊断工具,而非像差分隐私的数学边界那样的隐私保证。


## 解读 NNDR 图

- 大多数合成记录的 NNDR 接近1。最近和次近的真实记录大致等距。**合成数据并未复制真实记录。**
- 在 NNDR = 0 附近确实出现了一个尖峰:在抽样的500条合成记录中,约有4%(20条)在 `Age`、`Density` 和 `Value` 三个变量上,与某一条真实记录的距离恰好为零。这并非完整记录的记忆现象。`synthpop` 的 CART 方法是从其拟合树中匹配叶节点内*实际观测到的取值*中抽取每一个数值,而非做平滑或加入噪声,因此一条合成记录的 `Age`/`Density`/`Value` 组合,有可能恰好与某一条具体真实记录的组合完全一致,尤其是因为该数据集中 `Density` 在8,000条记录中只有471个不同取值。检查这些完全匹配的案例可以看到,分类变量(`Group1`、`Bonus`)以及理赔结果,通常仍与该合成记录的数值最近邻真实记录不同,因此整条记录并非复制,但在看似连续、实则基数有限的变量上出现完全匹配,正是下文提到的成员推断检验所要捕捉的那类残余风险。
- 由于 CART 在 `minbucket` > 1 时会在每个叶节点引入随机性,使用 CART 的 `synthpop` 通常能取得良好的 NNDR 表现。

::: {.callout-note title="案例研究揭晓:回答开篇提出的三个问题"}
**问题一:哪一位接收方可以被正当地提供 k-匿名化数据?再保险公司所掌握的部分背景信息,是否会改变你的答案?**

可以说,三者都不适合——但这并非因为 k-匿名性本身有缺陷,而是因为对这三份具体的申请而言,它都不是恰当的工具。再保险公司需要真实感的记录级数据来构建独立模型,而 k-匿名性只会降低这类数据的质量,而非提供它;内部团队根本不需要一份被降质处理过的文件;供应商则完全不需要任何文件。而在 k-匿名性原本可能适用的情形下,背景知识确实会改变答案:本章自己在 $k=50$ 下的结果表明,`Gender`(性别)、`AgeGroup`(年龄组)、`DensityGroup`(密度组)——恰恰是一家在往年分保合约中接触过部分保单持有人的再保险公司,最有可能已经掌握的变量——完全未受抑制的影响,因此“隐藏在 $k$ 个他人之中”这一论证,对这一特定接收方而言,要比对一个毫无背景知识的外部者弱得多。

**问题二:定价团队需要真实感(而非真实)的数据,这是否意味着必须使用合成数据,还是存在更简单的答案?**

更简单的答案是:根本不需要任何隐私增强技术,只需要治理措施。定价团队身处内部,已经受保密义务约束,且无论用什么数据训练,其模型最终都会针对生产环境中的真实数据进行验证。将合成的精力花在一个并不需要它、且从组织内部已有数据中也得不到任何额外隐私收益的接收方身上,是一种用错了地方的努力。下文生命周期管控表中“分析/建模”一行所列的用途限制与基于角色的访问控制,才是相称的管控措施。

**问题三:供应商只需要汇总统计量,这是否排除了本章三种技术中的两种?**

是的。k-匿名性和合成数据都是为保护*文件*而生,而供应商从未收到过文件。这样一来,**差分隐私**就成了三种技术中唯一相关的选择,本章自己的结果也表明,在这一业务组合的规模下,强隐私性(较小的 $\varepsilon$)对于一个业务组合层面的统计量而言,几乎不会带来任何准确性代价,只要监管机构日后不要求按更小的子群体进行更精细的分解。

**简而言之:** 再保险公司适用合成数据(TSTR:AUC 0.728 对 0.729,仍需受限于前文提到的成员推断这一附加检验),内部团队仅需治理措施,供应商适用差分隐私。三位接收方,三种不同的工具,而非用同一种技术一概而论。
:::

# 小结

- **重新识别风险** 即便在大型的“匿名化”数据集中依然真实存在。准标识符的组合能够唯一识别出罕见群体,而同样的风险评估工作流程(识别准标识符 → 选择匹配的隐私增强技术 → 应用 → 衡量权衡取舍 → 决策)也可迁移至其他领域。
- 通过局部抑制实现的**k-匿名性**降低了可识别性,但并不保护敏感取值,而且一旦 $k$ 大到足以迫使真正的抑制发生(而不只是教科书式的最小值 $k = 5$),效用代价就会迅速上升。
- **差分隐私** 提供数学上的保证,并能很好地适应大型数据集:同样的 $\varepsilon$,对100,000条记录的汇总统计量几乎没有影响,但对一个小型子群体却可能造成明显失真,因为敏感度按 $1/n$ 缩放。拉普拉斯机制对汇总统计量而言实现起来很直接。
- 来自 `synthpop`(CART)的**合成数据**在边际分布和模型系数上取得了良好的保真度,一个在其上训练的模型在留出的真实记录上(TSTR)的表现也几乎与在真实数据上训练的模型一样好,NNDR 证据也表明真实记录并未被复制。
- 没有任何单一技术本身是充分的——需要在整个数据生命周期中采取**分层管控措施**。
